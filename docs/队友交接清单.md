**前置条件**

  换台机器前先用 `Get-NetTCPConnection -State Listen -LocalPort 8080` 查一下
- 详细背景见 `docker/README.md`，未验证项就是下面这张表

**逐条核对（全在 `docker/` 与仓库根目录下执行）**

| # | 验什么 | 命令 | 通过的标准 | 不通过怎么办 |
|---|---|---|---|---|
| M1 | compose 语法 | `docker compose -f docker/docker-compose.yml config -q` | 退出码 0，无输出 | 贴报错原文 |
| M2 | nginx 配置语法 | `docker compose -f docker/docker-compose.yml run --rm front nginx -t` | 看到 `syntax is ok` / `test is successful` | 贴报错原文 |

| M8 | **端到端实跑** | 见下 | 退出码 0，生成 `results/real.md` | 见下 |

**M8 端到端实跑（这是最关键的一条）**

```powershell
powershell -NoProfile -File docker/up.ps1
python -m ced scan --topology ced/topologies/real-nginx-probe.yaml --limit 12 --out results/real.md --poc-dir results/pocs
powershell -NoProfile -File docker/down.ps1
```

**通过的标准**：扫描那条命令退出码 0，并打印出这样的四行：

```
--------------------------------------------------------------
[结果] 用例 12 | 实现对 5 | 耦合误差 <D> | 安全级 <S>
[产物] results/real.md
[产物] results/pocs  （<K> 个端到端 PoC 脚本）
```

`D` 和 `S` 是几不重要（取决于 nginx 版本怎么定帧），**能稳定跑完、报告与 PoC 都能生成**就算过。

**两件必须知道的事**

1. **`--limit 12` 不能省。** 探针要等客户端半关闭写端才处理请求，而 nginx 不对上游半关闭，
   所以走真实前置时**每条约 5 秒**。`--limit 12` 大约 3 分钟。先用少量用例把流程走通再放量。
2. **看到这行是正常的，不是故障**：
   ```
   [说明] 前置按自身策略拒绝了 N 条用例（后端视角不存在），已跳过 —— 不合成观测，也不中止扫描
   ```
   真实 nginx 对畸形请求（比如 `Content-Length: abc`）会直接 400 且不向后端转发。
   工具把这类用例**跳过并计数**，既不伪造观测也不中止 —— 这是刻意设计，不是 bug。

**不通过怎么办**：先跑 `docker compose -f docker/docker-compose.yml ps`，再
`docker compose -f docker/docker-compose.yml logs front` 与 `logs probe`，
三段一起贴回来。**不要自己改 compose 或 nginx.conf。**

**验证完全部通过后**，请把 M8 的真实输出（四行 + 那行「已跳过」）补进 `docker/README.md` 的
「本机实测」一节，并把未验证清单里对应的行打勾。

## 任务二：录演示视频（≤ 5 分钟，**本机就能录，不需要 Docker**）

按顺序录，边录边念一句话。总时长约 4 分 40 秒。

| 镜头 | 时长 | 操作 | 要念的一句话 |
|---|---|---|---|
| 1 | ~25s | `python main.py --check` | 「先证明程序本身是好的：175 项自动化测试 + 47 个已知案例全部通过。」 |
| 2 | ~60s | `python main.py` → 在「扫描」页把用例上限填 20 → 点「开始扫描」 | 「全程零第三方依赖，这是本机的实时进度。」 |
| 3 | ~70s | 滚到下面的**指标卡**与**交叉矩阵热力图** | 「指标自动出数；矩阵里越深表示这对实现分歧越多，红色是安全级。」 |
| 4 | ~90s | 在左边点开一条**安全级**发现，从上往下滚完证据视图 | 「请注意这一栏是『已证实 · 内核产出』：双侧观测、消融证据、最小复现样本；链式复现直接给出被夹带多少字节。」 |
| 5 | ~40s | 继续滚到最下面的「攻击场景与复现步骤」，点开「展开可执行 PoC 脚本」 | 「大模型的叙述被单独放在灰色的『未验证』栏里 —— 它只能提案，判定权在内核。」 |

**注意**：镜头 6 里的 `<case_id>` 用镜头 4 里选中的那一条（屏幕上就有）。
如果那一条的 `case_id` 是 `8b2611d2`，命令就是 `python -m ced poc 8b2611d2`。

**可选镜头（配了模型才录）**：

```bash
python -m ced agent --rounds 4 --limit 60     # 闭环：模型看上一轮结果决定下一步往哪搜
```

没配模型时这条命令也能跑（会自动降级为单轮确定性扫描），但演示效果不如配上模型。

## 出问题时

- 自检不绿 → 什么都别做，把 `python main.py --check` 的完整输出贴上来。
- Docker 起不来 → 贴 `docker compose ps` + `logs front` + `logs probe`。
- 扫描很慢 → 正常，见任务一的提醒；先减 `--limit`。
- 看到一堆「已跳过」→ 正常，见任务一的提醒。
- **任何情况下都不要改 `ced/` 下的代码。**
